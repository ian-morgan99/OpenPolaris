THE QUESTION
------------
User built custom firmware that should have included a working camera
driver (PTP/MSC). After install attempts, the on-device FwVer is still
4.0.0.32 (2025-05-09) — the factory build. Why didn't the new firmware
install?

THE ANSWER (one line)
---------------------
The installer DID run, but the firmware package failed its integrity
check, and the installer's own cleanup path wiped the SD card. New
firmware was never written to NAND.

3. The upgrade script
---------------------
/app/getFwInfo.sh expects:

7. The CRC/MD5 path
-------------------
Both /app/sd/FwPkt/crcInfo and /app/sd/OmsPkt/crcInfo have a
"fopen crcInfo failed!" branch — which is also what the firmware ships
if no package is present. The state machine then doesn't fire.

But the binary was clearly being called with the FwPkt path (strings
include s_stExdevUpgrade.fwFileName and s_stExdevUpgrade.version), so
this was a real install attempt, not a probe.

WHY THE INSTALL FAILED
======================
Most likely causes, in order of probability:

A. Wrong CRC pre-computed in the package
   - getFwInfo.sh runs on the host PC to make crcInfo. If the host
     image and the device image don't match exactly (e.g. different
     u-boot header, different salt), MD5 mismatches.
   - The script expects a literal FwPkt/ tree with file names
     case-exact. A zip with a parent dir like polaris_pkg/ instead of
     FwPkt/ will fail silently.

B. Wrong hardware revision
   - SP_GetFactoryParam from Mlog_000002.log:
       hw:1.1;date:2021.11.29;pcb:1.20;modif:usb
   - The modif=usb flag means the device was factory-modified for
     USB use. Some firmware packages are pinned to a specific hw/pcb
     pair and refuse to flash outside it.
   - The "uImage" inside FwPkt/camera/ must be built for this exact
     board; otherwise the kernel will fail its own post-flash check.

C. SD card format issue
   - The card is vfat with codepage=437 shortname=mixed. If the
     firmware package is too large or the card is exFAT, the unzip
     step writes nothing.
   - The "errors=continue" mount option means the kernel tolerates
     filesystem errors silently — so a corrupt FAT might be why MD5
     mismatch occurs (crcInfo reads a partial file).

D. Permission/UID mismatch
   - /app/sd is mounted with fmask=0022, dmask=0022 — readable by all,
     writable only by root. But the FwPkt subdirectory may be created
     with 0755 owned by the user that ran unzip. If polestar_app runs
     as user 1000 (it does, from stat: Uid 1000 UNKNOWN), it CAN
     read the files, but might fail to write to /app/sd/ExDevFwPkt
     during its second unzip.

NEXT STEPS
==========
User has 10 candidate FwPkt.zip packages to test.

For each candidate:
  1. Stop polestar_app:
       pkill polestar_app
     This stops the auto-cleanup race.
  2. scp the zip to the gimbal:
       scp <local-zip> root@192.168.0.1:/app/sd/FwPkt.zip
  3. Snapshot what's on the card:
       ls -la /app/sd/
       md5sum /app/sd/FwPkt.zip
  4. Start polestar_app again so the upgrade state machine runs:
       cd /app/bin && nohup ./polestar_app >> /app/Mlog.txt &
  5. Tail logs in another window:
       tail -f /app/Mlog.txt
     Look for:
       OMS_UPGRADE_STA_CHECK_FW PASS/FAIL
       crc[%d] != %d
       SP_EVENT_UPGRADE_SUCCESS / FAIL
       EXDEV_UPGRADE_STA_*
  6. If SUCCESS — wait for the auto-reboot. After reboot, verify:
       cat /app/FwVer       (should change)
       stat /app/bin/pgphoto (should change)
  7. If FAIL — capture the first FAIL log line, save the SD card
     contents for offline analysis, try next package.

SAFETY
------
- The first 5 packages should be treated as the "safe" ones (closer
  to the factory revision). Save the most-aggressive rebuild for
  last.
- The appfs.ubifs is what overwrites /app. A bad one can brick the
  userland. Keep a serial console / SSH fallback ready — if SSH goes
  away after the appfs write, only the recovery UART can save it.
- Each FwPkt.zip should fit in the 121 MB free SD space. If not, copy
  the contents directly via /app/sd/FwPkt/ instead.
