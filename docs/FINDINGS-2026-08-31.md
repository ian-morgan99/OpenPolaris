# Findings — 2026-08-31

**Branch:** `agents/connectivity-tests-for-polaris`
**Scope:** Parser hardening for live-captured wire-format quirks + 12 new test cases.

## What changed

### 1. ResponseParser hardened (commit `736f35b`)

`shared/.../protocol/ResponseParser.kt` — `parseFields` companion rewritten to tolerate
two live-captured (gimbal sw:6.0.0.54) wire-format quirks the prior version dropped or
corrupted:

| # | Quirk | Live wire | Old behaviour | New behaviour |
|---|-------|-----------|---------------|----------------|
| 1 | Camera-code errors echo `-100` as field prefix | `258@-100ret:-1;#` | stored `{key='-100ret', value='-1'}` | strips `-100`, stores `{key='ret', value='-1'}` |
| 2 | 525 connect-burst pushes angle-bracket envelope with no colon | `525@Temp<a509ca361e0000275a>;#` | silently dropped whole segment | extracts `name<value>`, stores `{key='Temp', value='<a509ca361e0000275a>'}` |

Both classes of fix were independently verified against a Python port of the hardened
parser — 12/12 wire-format quirks round-trip cleanly
(`/tmp/parser-test/verify-hardened.py`).

### 2. Twelve new ResponseParserTest cases

`shared/.../ProtocolTest.kt` now contains 24 `ResponseParserTest` methods:

- 12 originals (untouched, still pass against the rewritten parser)
- 12 new, each driven by a real captured wire payload

The new cases cover: 258/259/260/261/263/276 camera-code error echoes, 525 angle
envelope (both single and as part of a connect-burst), 264 missing-trailing-semicolon
(quirk from 2026-08-30 capture), 264 state-mirror `-1002` value, mixed 258+524+778
burst, and the `-100`-alone empty-sentinel regression guard.

## Pre-existing infrastructure issue (not caused by this work)

Full `:shared:jvmTest` run fails with `ClassNotFoundException` for **every** test class
in the worktree, not just the protocol ones. Examples from
`shared/build/reports/tests/jvmTest/index.html`:

- `AstroMathTest.initializationError[jvm]`
- `CameraProfileTest.initializationError[jvm]`
- `MountSessionTest.initializationError[jvm]`
- `ResponseParserTest.initializationError[jvm]`

The XML reports show stale timestamp `2026-08-31T13:47:55` — Gradle is not
regenerating them even with `--rerun-tasks`. The `--tests` filter does not exhibit
the same failure (it loads the class via a different code path), but does not write
XML test-results. This is a worktree-level test discovery / classpath problem that
predates the parser edit.

**Authoritative verification** for the new test logic therefore comes from the
Python port, not from `./gradlew :shared:jvmTest`, until the infrastructure is
fixed.
