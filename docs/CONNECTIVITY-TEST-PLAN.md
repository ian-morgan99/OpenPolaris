# Open Polaris — Connectivity Test Plan (Physical Device)

> Generated by the connectivity-test worktree. Drives the existing `:tools:cli-probe` CLI
> through every protocol code documented in `PROTOCOL.md`. No fixtures, no mocks — every
> frame hits the real mount on `192.168.0.1`.

## Pre-flight (L2 / L3 only — no protocol needed)

These four run before any probe. If they fail, do not proceed.

| #  | Action                                            | Expected                              | Pass |
|----|---------------------------------------------------|---------------------------------------|------|
| 0.1| `nmcli dev wifi list`                              | Polaris SSID visible                  | ☐    |
| 0.2| `nmcli dev wifi connect <SSID> password <PASS>`   | wlp8s0 obtains 192.168.0.x lease      | ☐    |
| 0.3| `ping -c 3 192.168.0.1`                           | 0% loss, <10 ms                       | ☐    |
| 0.4| `nc -vz 192.168.0.1 9090 ; nc -vz 192.168.0.1 8080` | both succeed                          | ☐    |

The probe defaults to `192.168.0.1:9090`; override with the last two args of any subcommand.

## Probe usage (every test below uses one of these)

```bash
# 1. Status poll (default mode — equivalent to 1.1 in SMOKE-TEST.md)
./gradlew :tools:cli-probe:run

# 2. One-shot: build a frame with `k:v;...` payload, send, print response
./gradlew :tools:cli-probe:run --args="send <code> [payload]"

# 3. Burst: send same code N times, summarize responses
./gradlew :tools:cli-probe:run --args="burst <code> <count>"

# 4. Listen: open socket, no send, read frames for N seconds
./gradlew :tools:cli-probe:run --args="listen <code> <seconds>"
```

Payload format: `key:value;key:value;` — e.g. `state:1;speed:0;`. Unknown keys are
passed through; the parser on the device handles them.

## Risks & open questions for the user

1. **Camera tests** — are we confident a body is mounted, SD is clear, and
   "fire once" is acceptable? If not, gate section 5.
2. **Lat/lng for `519` goto and `530` alignment** — defaulting to (0, 0) for a
   "responds" smoke; if you want a real aim, provide current GPS.
3. **AP SSID/passphrase** — most Benro Polaris units broadcast a default
   `Benro_XXXX` with a stock passphrase. Confirm before `nmcli connect`.

## What I do NOT do unilaterally

- Trigger a camera shutter (5.5)
- Reorient the mount via `549 SET_AUTO_LEVEL_STATE` (skipped)
- Run tracking on the actual sky without a clear "go"
- Connect to a non-Polaris SSID, even if it's the only one available
